## Flagged Assumptions

- **Zeilenangaben:** `read_first`-Zeilen stammen aus dem Stand beim Planen; maßgeblich sind die genannten Bezeichner.
- **Basis:** 03.1.1-01 bis -03 sind ausgeführt: Tabelle `vocabulary_picture` mit Mandantenfilter und ohne Navigation an `VocabularyEntry`, `GET /api/v1/pictures/{version}` für jede Rolle der Familie, `VocabPicture` (Rahmen fester Größe mit `data-testid="vokabelbild"`, `variant="large"` = `size-40 rounded-sm`, Bild `object-contain`, beim Laden leer, bei Lade- oder Dekodierfehler `fallback` im selben Rahmen), `PictureQueryTests` mit Recorder und Detektor `SelectsPictureBytes`, e2e-Helfer `canvasPicture`, `accessToken`, `putPicture` in `frontend/e2e/pictures.ts`, Byte-Hilfen und `PutPictureAsync` in `PictureTests`.
- **Server (Recherche „Lernrunde“, Pitfall 4):** `SessionItemView` bekommt `Guid? PictureVersion` direkt nach `Emoji`. `BuildItemView` bekommt den Parameter `Guid? pictureVersion`. `BuildItemViewsAsync` holt nach den Karten eine Hilfsabfrage `db.VocabularyPictures.Where(p => entryIds.Contains(p.Id)).Select(p => new { p.Id, p.Version })` als Wörterbuch (Schlüssel = Vokabel-Id) und reicht je Karte die Version durch. Der Retry-Pfad (`retryView = BuildItemView(retry, card, …)`) fragt die Version der einen Vokabel per Projektion ab (`Where(p => p.Id == card.EntryId).Select(p => (Guid?)p.Version).FirstOrDefaultAsync(ct)`). Eine Navigation, die Bytes mitladen könnte, gibt es seit 03.1.1-01 nicht. Der Mandantenfilter gilt für beide Abfragen; das Kind sieht nur Bilder der eigenen Familie.
- **SQL-Nachweis (Review MEDIUM, Codex 03.1.1-03):** `PictureQueryTests` bekommt zwei Fälle: Rundenstart (`POST /api/v1/sessions` als Kind) und falsche Antwort mit `retryItem` (`POST /api/v1/sessions/{id}/answers`). Je Anfrage: mindestens ein aufgezeichneter Befehl nennt `vocabulary_picture` (die Version wird gelesen), keiner löst `SelectsPictureBytes` aus. Vor dem Code nennt kein Befehl die Tabelle, der Fall ist also rot. Er ersetzt den Größentest des ersten Planstands.
- **Beide Richtungen bekommen das Bild** (Recherche Muster 7), wie heute das Emoji (`Emoji: entry.Emoji` unabhängig von der Richtung).
- **Alt-Text (D-11, Recherche Muster 7):** `alt=""`. Das Bild ist Merkhilfe zum Prompt, der direkt darunter als Text steht; „das Wort der Frage“ wäre eine Doppelansage, eine Bildbeschreibung verriete in Richtung EN→DE die Lösung. Das Emoji ist heute schon `aria-hidden`.
- **Anzeige (D-11, D-16):** In `SessionPage.tsx` ersetzt `current.pictureVersion ? <VocabPicture version={current.pictureVersion} variant="large" alt="" fallback={Emoji-Span oder null} /> : (Emoji wie bisher)` den Emoji-Block (`SessionPage.tsx` `{/* card-quiz */}`). Der Emoji-Span bleibt unverändert (`type-emoji`, `aria-hidden`). Hat die Vokabel ein Bild, aber kein Emoji, und das Bild lädt oder dekodiert nicht, bleibt der leere Rahmen stehen (kein Layoutsprung). Das Antwortfeld behält `autoFocus`; der reservierte Rahmen verhindert, dass es beim Nachladen wandert (Recherche Pitfall 6).
- **Typ:** `SessionItem` in `frontend/src/types.ts` bekommt `pictureVersion: string | null` direkt nach `emoji`.
- **e2e ohne Secure Context:** Die neuen Tests liegen im Block `test.describe('ohne Secure Context')` von `learn.spec.ts` (baseURL `http://wordquest.test:18080`, dort ohne Service Worker, `page.route` sieht also auch GET-Antworten; mit Service Worker bräuchte es `serviceWorkers: 'block'` wie im Block zur Startseite). Jeder Test legt wie „Abgebrochene Runde“ ein eigenes Kind an (damit das Tagesbudget des Demo-Kinds für „Lernen über HTTP“ unberührt bleibt), über einen Eltern-Kontext mit der baseURL des Projekts (`test.info().project.use.baseURL`, dort gilt `guardianStorageState`). Set und Vokabel legt der Eltern-Kontext per API mit Token an (`POST /api/v1/sets` mit `CreateSetRequest`, `POST /api/v1/sets/{id}/entries` mit `CreateEntryRequest`), das Bild per `canvasPicture` und `putPicture`. Das Set hat genau eine Vokabel, damit jede Karte der Runde ein Bild trägt.
- **Anmelde-Budget (Plan-Checker INFO):** Das Rate-Limit `auth` zählt je IP-Adresse, also je Gerät; im vollen e2e-Lauf teilen sich alle Tests eine Adresse. Jeder neue Test kostet wie „Abgebrochene Runde“ zwei Anfragen der Policy `auth` (einmal `/` mit `GET /auth/profiles`, einmal `learner-login`); der Eltern-Kontext nutzt `guardianStorageState` und meldet sich nicht neu an. Der Teststack hebt das Limit auf 1000 je Minute (`Auth__RequestsPerMinute` in `frontend/e2e/docker-compose.e2e.yml`); `openPicker` und `sendLogin` machen ein 429 sichtbar.
- **Dekodierfehler im e2e (Review MEDIUM):** Der Server nimmt nur strukturell schlüssige Bilder an; einen Dekodierfehler nach HTTP 200 erzeugt deshalb `page.route` auf `GET /api/v1/pictures/…` mit `route.fulfill({ status: 200, contentType: 'image/png', body: 'kaputt' })`. Erwartet: im Rahmen `vokabelbild` steht das Emoji der Vokabel, kein sichtbares `img`, die Höhe des Rahmens ist 160 px (`boundingBox`), genau wie mit dekodierbarem Bild im Test „Lernen mit Bild über HTTP“.
