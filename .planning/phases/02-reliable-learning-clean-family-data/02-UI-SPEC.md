### Lernrunde (FIX-04), Texte für Kinder

Der Server liefert `detail`, die Fehleransicht der Runde zeigt es in `ErrorNote` (Bestand `SessionPage.tsx:139-148`).

| Fall | Status | `detail` |
|------|--------|----------|
| Antwort/Abschluss: Runde unbekannt oder fremd | 404 | Diese Runde gibt es nicht mehr. Starte eine neue Runde. |
| Antwort: Karte gehört nicht (mehr) zur Runde | 404 | Diese Karte gehört nicht zu dieser Runde. Starte eine neue Runde. |
| Antwort: Doppel-Tipp, gleichzeitig angekommen | 409 | Diese Antwort ist schon angekommen. Starte eine neue Runde, um weiterzulernen. |
| Start: Kind unbekannt (Elternkonto, fremde ID, gelöschtes Kind) | 404 | Dieses Kind gibt es nicht (mehr). |
| Start: `size` außerhalb 1–50 | 400, Schlüssel `size` | Eine Runde hat 1 bis 50 Karten. (Frontend schickt `size: null`, für Kinder unsichtbar) |
| Übersicht eines gelöschten Kindes (Gerät noch angemeldet) | 404 | Dieses Profil gibt es nicht mehr. Bitte melde dich ab. |

Button der Fehleransicht bleibt „Zurück“ (Bestand) und führt zur Startseite, wo „Los geht’s“ eine neue Runde startet.

### Token-Refresh (FIX-01)

Kein neuer Text. ### Dialog-Baustein (`frontend/src/components/ui/dialog.tsx`, neu)

Zwei Exporte, beide auf `@radix-ui/react-dialog`:

- **`Dialog`** — Hülle: Props `open`, `onOpenChange`, `title`, `description`, `role?` (`'dialog'` Standard, `'alertdialog'` für Bestätigungen), `initialFocusRef?`, `children`. Aufbau `Root` → `Portal` → `Overlay` + `Content` mit `Title` und `Description`.
- **`ConfirmDialog`** — auf `Dialog`: Props `open`, `onOpenChange`, `title`, `description`, `confirmLabel` („Endgültig löschen“), `busy`, `error?`, `onConfirm`. Inhalt: optional `ErrorNote`, dann Button-Zeile „Abbrechen“ (`secondary`) und Bestätigen (`danger`, `Trash2`-Icon).

Gestaltung (nur Tokens):
- `Overlay`: `fixed inset-0`, Fläche `components.sheet-scrim` (`colors.scrim`, neu in `DESIGN.md`), kein Blur.
- `Content`: `components.sheet` — `glass-sheet` (bringt den deckenden Fallback bei `prefers-reduced-transparency` und ohne `backdrop-filter` mit), `rounded-sheet` (44 px), `p-6`. Unten verankert mit `spacing.sheet-inset` (Stufe 2) Abstand zu linkem, rechtem und unterem Rand, `max-w-md`, waagerecht zentriert, Höchsthöhe Viewport minus 2 × `sheet-inset`, darüber `overflow-y-auto`. `flex flex-col gap-4`.
- `Title`: `h2`, `type-headline text-ink break-words`. `Description`: `type-body-md text-ink-soft`.
- Button-Zeile: `flex flex-wrap gap-2`, Buttons `flex-1`, Größe `md`. DOM-Reihenfolge = Sichtreihenfolge: „Abbrechen“ zuerst, Aktion danach. Bei 320 px brechen die Buttons in zwei volle Zeilen um.
- Keine Ein-/Ausblend-Animation (keine neue Bewegung, wie Phase 1).

Verhalten:
- Fokusfalle, `aria-modal`, Ausblenden des Hintergrunds für Screenreader und Scroll-Sperre liefert Radix.
- Startfokus: `ConfirmDialog` auf „Abbrechen“ (`onOpenAutoFocus` mit `preventDefault` und Fokus auf den Ref). Formular-Dialoge auf das erste Feld (Radix-Standard: erstes fokussierbares Element).
- **Enter auf dem Startfokus „Abbrechen“ löscht nichts.** Löschen nur per Klick/Enter/Leertaste auf „Endgültig löschen“.
- Esc und „Abbrechen“ schließen ohne Änderung. Klick auf den Scrim schließt **nicht** (`onPointerDownOutside` und `onInteractOutside` mit `preventDefault`), damit weder versehentlich gelöscht noch Eingaben verworfen werden.
- Während `busy` ignoriert `onOpenChange` das Schließen.
- Fokusrückgabe: Radix gibt den Fokus an das vor dem Öffnen fokussierte Element zurück (den Auslöser). Ausnahmen, weil der Auslöser verschwindet: Vokabel gelöscht → Fokus auf den Set-Titel (`h2` mit `tabIndex={-1}`); Set oder Kind gelöscht → Navigation zur Liste, die `SuccessNote` (`role="status"`) sagt das Ergebnis an (Muster „Kind anlegen“, Phase 1).
- `role="alertdialog"` für alle drei Löschungen (Radix `Content` mit `role`-Prop; `@radix-ui/react-alert-dialog` ist nicht installiert, D-15).
