## Phase Goal

> A parent installs WordQuest in the home network over plain HTTP with their own account, generated secrets and daily backups, and can recover their own password and a child's forgotten PIN without help

Hinweis (MVP-Modus): Das Ziel ist nicht als User Story formuliert; eine Story-Fassung entsteht nur über `/gsd-mvp-phase 1`.

## Artifacts this phase produces

Dieser Plan liefert "Kind anlegen" (PAR-05) mit serverseitiger PIN-Regel (PAR-02):
- `AccountRules.IsValidPin`, `MaxDisplayNameLength`; `CreateLearnerRequest` mit `DailyNewLimit`; Regeln im `LearnerEndpoints.CreateAsync`
- Seiten `ChildrenPage` (`/verwalten/kinder`) und `ChildFormPage` (`/verwalten/kinder/neu`), Tab "Kinder", "+" "Kind anlegen"
- Tests `LearnerEndpointTests`, erweiterte `AccountRulesTests`, `ChildFormPage.test.tsx`, `ChildrenPage.test.tsx`, `e2e/children.spec.ts`

## Flagged Assumptions (Probe: unclassified)

- **PAR-02 (unclassified):** Angenommen wird: Die PIN-Regel heißt genau 4 bis 6 Zeichen aus 0–9 (keine anderen Unicode-Ziffern, keine Leerzeichen, kein stilles Trimmen). Beim Anlegen ist die PIN Pflicht (D-08); beim Ändern (01-08) bedeutet ein leeres Feld "unverändert". Bereits gespeicherte PINs außerhalb der Regel bleiben gültig, bis die Eltern sie ändern.

<assumption_delta_decision>
- Detector: pluralization ("also when sent directly to the API").
- Primary noun: die serverseitige Regel `AccountRules.IsValidPin` (Identity-Modul).
- Decision: promote — der Server ist die einzige Autorität für die PIN-Regel über alle Kanäle (Formular, direkter API-Aufruf); das Formular spiegelt sie nur für sofortige Rückmeldung.
- Invariant test: `LearnerEndpointTests` prüft in diesem Plan das Anlegen; 01-08 ergänzt eine Theorie, die dieselben ungültigen PINs gegen POST und PATCH schickt (beide 400 pin).
</assumption_delta_decision>

Ein Elternteil legt in der App ein Kind mit Name, Tageslimit und PIN an; auf einer frischen Installation ist das der einzige Weg zum ersten Kind. Der Server erzwingt die PIN-Regel (4–6 Ziffern) und die Namenslänge, auch bei direktem API-Aufruf.

Purpose: PAR-05 (D-08), PAR-02 (Anlegen), QUAL-02 (Formular-Matrix und axe); Grundlage für Kind bearbeiten (01-08).
Output: Server-Regeln, Kinderliste, Anlege-Formular, Tests.
