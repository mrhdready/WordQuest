## Phase Goal

> A parent installs WordQuest in the home network over plain HTTP with their own account, generated secrets and daily backups, and can recover their own password and a child's forgotten PIN without help

Hinweis (MVP-Modus): Das Ziel ist nicht als User Story formuliert; eine Story-Fassung entsteht nur über `/gsd-mvp-phase 1`.

## Artifacts this phase produces

Dieser Plan liefert "Passwort ändern" Ende-zu-Ende und schließt das Frontend-Gate:
- Endpoint `POST /api/v1/account/password` (`AccountEndpoints`), `AccountService.ChangePasswordAsync`, Enum `PasswordChange`, `ChangePasswordRequest`
- Seite `AccountPage` unter `/verwalten/konto` mit Tab "Konto", `SuccessNote` in `misc.tsx`
- Tests: `AccountEndpointTests` (PostgreSQL), `AccountPage.test.tsx` (Matrix über die Testhilfe aus 01-03), `e2e/account.spec.ts`
- CI und AGENTS.md-Gate um `npm test`, `design:check`, `design:classes`; bekannte Lücke D-18 dokumentiert

## Flagged Assumptions (Probe: unclassified)

- **SETUP-03 (unclassified):** Angenommen wird: Ein Passwortwechsel beendet keine anderen Sitzungen (UI-SPEC "Anmeldung bleibt bestehen"); die Prüfung gegen Listen häufiger Passwörter ist nicht Teil von v1 und wird als bekannte Lücke dokumentiert (D-18). Der Endpoint liegt unter dem Rate-Limit `auth`, damit das aktuelle Passwort nicht unbegrenzt geraten werden kann.
