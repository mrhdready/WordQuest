## Phase Goal

> A parent installs WordQuest in the home network over plain HTTP with their own account, generated secrets and daily backups, and can recover their own password and a child's forgotten PIN without help

Hinweis (MVP-Modus): Das Ziel ist nicht als User Story formuliert; eine Story-Fassung entsteht nur über `/gsd-mvp-phase 1`.

## Artifacts this phase produces

Dieser Plan liefert "Kind bearbeiten" (PAR-01) und schließt PAR-02 für das Ändern; er ist der letzte Plan der Phase:
- `UpdateLearnerSettingsRequest.DisplayName`, PIN- und Namensregeln im PATCH (gemeinsam mit POST)
- Modus Bearbeiten in `ChildFormPage` (`/verwalten/kinder/:learnerId`), Kinderliste mit Zeilen-Links
- Tests: PATCH-Integrationstests, Edge-Case-Matrix Bearbeiten, e2e Bearbeiten + Anmeldung mit neuer PIN, axe
- Phasen-Abschluss-Gate (siehe `<verification>`)

## Flagged Assumptions (Probe: unclassified)

- **PAR-01 (unclassified):** Angenommen wird: Bearbeiten bleibt auf der Seite (kein Weiterleiten), leert danach das PIN-Feld und aktualisiert die Liste. Ein leeres PIN-Feld bedeutet "PIN unverändert"; ein PIN-Feld nur aus Leerzeichen ist ungültig (UI-SPEC Fehlerfall "Leerzeichen"). Am Server lautet der Fehlertext für einen leeren Namen beim PATCH wie beim POST (Bestandswortlaut `LearnerEndpoints.cs:52`, UI-SPEC "Bestehende Servertexte bleiben unberührt"); das Formular fängt den Fall vorher mit dem UI-SPEC-Text ab.

<objective>
Ein Elternteil ändert Name, Tageslimit und PIN eines Kindes in der App; eine vergessene PIN wird so ohne Hilfe ersetzt, auch wenn das Kind gesperrt ist. Der Server erzwingt die PIN-Regel auch beim Ändern.

Purpose: PAR-01, PAR-02 (Ändern), QUAL-02 (Formular-Matrix und axe für Kind bearbeiten); Erfolgskriterien 4 und 5 der Phase.
Output: PATCH-Regeln, Bearbeiten-Modus, Tests, Phasen-Abschluss-Gate.
Ablauf (D-02): ein atomarer Commit pro Plan auf `v1-fertig`, kein Push.
</objective>
