## Phase Goal

> A parent installs WordQuest in the home network over plain HTTP with their own account, generated secrets and daily backups, and can recover their own password and a child's forgotten PIN without help

Hinweis (MVP-Modus): Das Ziel ist nicht als User Story formuliert; eine Story-Fassung entsteht nur über `/gsd-mvp-phase 1`.

## Artifacts this phase produces

Dieser Plan liefert Wiederherstellung und Absicherung des Betriebs:
- CLI-Verb `reset-password` (`AccountCommands`, `AccountService.ResetPasswordAsync`)
- `SecretCheck` und Startabbruch außerhalb von Development in `Program.cs`
- `backup`-Dienst in `docker-compose.quick.yml`, `backups`-Ordner und Abschlusstext in `setup.sh`
- Tests `ResetPasswordCommandTests`, `SecretCheckTests`; erweiterter Smoke `setup-smoke.sh`; Doku zu Backup, Reset und Startabbruch

## Flagged Assumptions (Probe: unclassified)

- **SETUP-04 (unclassified):** Angenommen wird: Der Reset wird über die E-Mail-Adresse eines Elternkontos (Rolle Owner oder Guardian) ausgelöst, nie für Kinderkonten; er widerruft alle Refresh-Tokens des Kontos (angemeldete Geräte müssen sich neu anmelden); Aufruf aus dem Installationsverzeichnis mit `docker compose exec api dotnet WordQuest.Api.dll reset-password <E-Mail>` (COMPOSE_FILE aus `.env`).

<objective>
Ein Betreiber, der sein Passwort verloren hat, setzt es mit einem Befehl im Container zurück und meldet sich mit dem Ergebnis an; die API verweigert außerhalb von Development den Start mit fehlenden oder bekannten Standard-Secrets; der Heimnetz-Stack sichert die Datenbank täglich.

Purpose: SETUP-04 (D-06), SETUP-05, Backup-Teil von SETUP-01; Erfolgskriterien 2 und 3 (Reset-Teil).
Output: reset-password, SecretCheck, backup-Dienst, erweiterter Smoke, Doku.
Ablauf (D-02): ein atomarer Commit pro Plan auf `v1-fertig`, kein Push.
</objective>
