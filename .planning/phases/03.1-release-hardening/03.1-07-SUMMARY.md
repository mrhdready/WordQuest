```bash
[[ "$(gunzip -c "$1" | tail -n 20 | grep -cx -- '-- PostgreSQL database dump complete' || true)" -gt 0 ]] || return 1
```

**Test:** Release-Smoke, Abschnitt „Vollstaendigkeitspruefung der Sicherung“. Er läuft vor dem Image-Build und nimmt `check_dump` per `sed` und `eval` aus dem ausgelieferten Skript. Mit `declare -f` scheitert der Fall, wenn die Funktion fehlt. Je Skript fünf Fälle:

| Fall | Inhalt | erwartet |
|---|---|---|
| `heute` | Ende wie pg_dump 17.6 | 0 |
| `plus1` | eine Zeile mehr nach dem Ende | 0 |
| `plus-lang` | drei Zeilen à 100 000 Zeichen nach dem Ende | 0 |
| `cut` | bricht mitten im COPY ab, gzip schließt sauber | 1 |
| `cut-text` | wie `cut`, die letzte Datenzeile enthält den Text der Endzeile | 1 |

**Rot-Belege:**
- `45f42e4` mit dem alten Code: `/bin/bash release-smoke.sh` → Exit 1, `RELEASE-SMOKE FEHLER: restore.sh: check_dump fuer Dump 'plus1' endete mit 1 statt 0.`. Für `upgrade.sh` einzeln: `plus1: abgelehnt (Exit 1)`.

- `ede49c5` gegen `f1f6cfc`: 5 von 5 Läufen Exit 1, `check_dump fuer Dump 'plus-lang' endete mit 1 statt 0.`

**Grün:** Abschnitt einzeln je 5 Läufe `DUMP-PRUEFUNG OK`. Im Release-Smoke auf END steht `DUMP-PRUEFUNG OK` (Task 1).

**Regression unterwegs (ehrlich vermerkt):** Der erste Release-Smoke auf `b156dc2` (mit `tail -n 20 | grep -qx`) endete mit Exit 1. Im Fall Importfehler meldete `restore.sh` „Die Sicherung des heutigen Stands ist fehlgeschlagen.“, danach folgte `RELEASE-SMOKE FEHLER: backups/fehlerhaft.sql.gz: Meldung nennt keine vorhandene Vorher-Datei.`.

  - `tail -n 5 | grep -qx`: 0 Fehler
  - `tail -n 20 | grep -qx`: 3 Fehler

- Der Fix `0c8d839` nutzt dasselbe Muster wie `check_dump` für `COPY public.app_user`.
