# Quick 261026-j98: Codex-Befunde der Wartungsrunde beheben

Ziel: Die fuenf bestaetigten Befunde sind je durch einen zuerst roten Test belegt und behoben; volles Gate gruen. Kommt mit in Release 1.1.0.

## Tasks

### Task 1 (MEDIUM): upgrade.sh und restore.sh pruefen HTTPS vor „Fertig“
- Befund: `upgrade.sh:204-212` und `restore.sh:142-150` (`start_app`) warten nur auf `/health/ready` der API und starten web neu. Bei kaputter CA (z. B. nur `ca.key`, kein `ca.crt`/`server.pem`; `certs` verweigert den Start, `TlsCommand.cs:~234`) melden beide trotzdem Erfolg.
- Fix: Dieselbe Wartelogik wie `setup.sh` (`wait_cert`/`wait_https`, `tls show`, `curl --cacert`) wiederverwenden – Bestand zuerst, keine zweite Variante erfinden. Scheitert sie: upgrade.sh ueber den bestehenden Fehlerweg (`start_failed` mit Weg zurueck), restore.sh mit Exit != 0 und dem Ausweg „Zertifizierungsstelle neu anlegen“ aus `Documentation/Installation.md`. Pruefen, ob die Funktionen in upgrade/restore als Kopie oder ueber gemeinsame Einbindung kommen; die Paketliste (5 Dateien) bleibt unveraendert, also keine neue Datei.
- Test zuerst: Fall im Install- bzw. Release-Smoke (oder setup-functions-check-Muster): CA-Volume in den Zustand „nur ca.key“ bringen, `upgrade.sh`/`restore.sh` ausfuehren → bisher Exit 0 und „Fertig“ (rot), danach Exit != 0 mit Meldung. Doku-Satz in Installation.md, falls die Meldung dort beschrieben werden muss.

### Task 2 (MEDIUM): CSV-Trennzeichen nur ausserhalb zitierter Felder zaehlen
- Befund: `CsvVocabularyParser.cs:~101` `DetectDelimiter` zaehlt Kandidaten auch in Anfuehrungszeichen; `"gehen, laufen, spazieren";go` wird als Komma-Datei erkannt und als ungueltig verworfen.
- Fix: Beim Zaehlen dieselben Quote-Regeln wie beim Zerlegen (verdoppelte `""` als Escape) anwenden.
- Test zuerst: Unit-Test im passenden Testprojekt mit genau dieser Zeile (plus eine zweite Zeile), erwartet 1-2 gueltige Eintraege mit Semikolon als Trenner.

### Task 3 (MEDIUM): Mindestlaenge fuer Tippfehler-Toleranz nach Artikel-Abzug
- Befund: `AnswerEvaluator.cs:71` prueft `candidate.Length` vor `StripOptionalLeadingWord`; erwartet `the dog`, Eingabe `dig` → richtig mit Tippfehler.
- Fix: Mindestlaenge auf den bereinigten Kandidaten anwenden.
- Test zuerst: Unit-Test in `backend/tests/WordQuest.Learning.Tests/`: `the dog` / `dig` → falsch; Gegenprobe `the elephant` / `the elefant` bzw. `elefant` → weiter richtig mit Tippfehler.

### Task 4 (LOW): Levelaufstieg durch Antwort-XP in der Runde wird gefeiert
- Befund: `LearningService.cs:355` liest `levelBefore` erst beim Abschluss; Antwort-XP sind dann schon gebucht → `LeveledUp=false`, UI „Geschafft!“ statt „Level N erreicht!“ (`SessionPage.tsx:392-396`).
- Fix (Orchestrator-Vorschlag, ohne Migration): `levelBefore = LevelCurve.LevelFor(profile.Xp - session.XpAwarded)` – `LearningSession.XpAwarded` haelt die in dieser Runde gebuchten XP vor dem Abschlussbonus. Vorher pruefen, dass XpAwarded wirklich nur Antwort-XP dieser Runde enthaelt (CreditAsync) und beim Zweitabschluss (claimed == 0) kein falsches LeveledUp entsteht.
- Test zuerst: Integrationstest (WebApplicationFactory, echtes PostgreSQL): Kind knapp unter Level-Grenze, eine richtige Antwort ueberschreitet sie, Abschluss → `leveledUp: true`.

### Task 5 (LOW): Ladefehler der Vokabelliste sichtbar
