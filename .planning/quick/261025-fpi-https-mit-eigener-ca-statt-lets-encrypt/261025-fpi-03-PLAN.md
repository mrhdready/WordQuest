Annahmen (im Plan festgelegt, in der Doku genannt):
- Zwei gleichzeitige Laeufe von setup.sh in derselben Installation werden nicht unterstuetzt (Orchestrator-Entscheidung zu Codex 1).
- Die Portpruefung bindet ueber Docker (`docker run --rm --entrypoint true -p <Port>:8080 <db-Image>`). In dieser Session auf macOS mit Docker Desktop geprueft: belegt erkannt bei einem Dual-Stack-Listener, einem reinen IPv6-Listener und einem von Docker veroeffentlichten Port; frei bei einem Listener nur auf 127.0.0.1 (macOS-Socket-Semantik). Unter Linux erkennt die Probe auch diesen Fall (Funktionspruefung, auf macOS mit benanntem Skip). Jeder Fehlschlag der Probe gilt als belegt; damit landet auch rootless Docker ohne Rechte fuer Ports unter 1024 beim Ausweich 8080/8443.
- Docker veroeffentlicht Ports mit dem Standard `userland-proxy: true`; ohne Proxy kann die Probe einen Fremd-Listener uebersehen, dann greift die Meldung beim Start (TOCTOU-Zweig).
</objective>
